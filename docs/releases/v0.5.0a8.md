# v0.5.0a8

Alpha pre-release for arduino-esp32 3.x Wi-Fi/BLE coexistence testing.

## Changes

- Moves automatic BMS discovery from blocking `NimBLEScan::getResults()` to
  callback-driven scanning so the main loop cannot sit forever waiting for a lost
  scan-complete event.
- Adds a 9 second BLE scan guard. If the controller never reports scan
  completion, the firmware stops the scan, resets NimBLE, and keeps the web/LVGL
  loop alive instead of waiting for the 30 second task watchdog.
- Initializes NimBLE before `WiFi.begin()` on normal STA boots with saved Wi-Fi
  credentials. Setup-AP boots still keep BLE off so provisioning remains stable.
- Uses lower-duty active scans with a 250 ms scan-response timeout to reduce
  Wi-Fi coexistence pressure while still allowing BMS devices that put UUIDs in
  scan-response data to be found.
- Blocks manual web BLE scans while automatic BMS discovery is active, avoiding
  two overlapping scan owners on the same NimBLE scanner.

## Testing Notes

- Expected serial logs:
  - `[BLE] init: internal heap before -> after`
  - `[BLE] BMS scan end: seen=N, match=yes/no, reason=..., heap=...`
  - `[BLE] BMS scan timeout ...` only if the controller wedges.
- If `seen=0` persists with a known nearby BMS, capture the serial log from boot
  through the first scan so we can compare init heap cost, scan end reason, and
  Wi-Fi events.
