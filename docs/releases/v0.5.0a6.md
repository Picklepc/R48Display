# R48Display v0.5.0a6 — alpha (arduino-esp32 3.x)

**Pre-release for hardware testing** — install over **USB** (see the v0.5.0a2
notes for why the first 0.5.x install can't be OTA). This build targets the two
connection problems reported on **v0.5.0a5**.

## Wi-Fi: stop reverting to the setup AP after connecting
The device would join your Wi-Fi, then fall back to the **setup AP about a minute
later "as if it never realized it connected."** The provisioning fallback reverted
to the AP whenever `WiFi.status()` read *not connected* for 30 s — but on core 3
that status can briefly read wrong right after the setup-AP → STA handoff, and any
normal Wi-Fi blip tripped it too.

- **Once the device has an IP it stays in STA and never auto-reverts.** A valid
  DHCP lease now counts as "connected," and transient drops simply retry STA.
- The automatic fallback to the setup AP now happens **only while validating
  brand-new credentials that have never connected** (i.e. a wrong password). A
  device that has connected — or booted with saved Wi-Fi — keeps retrying STA
  instead of being forced back to the AP. Use **Setup AP** on the display if you
  ever want to reconfigure deliberately.

## Bluetooth: diagnostics to find why no devices are seen
BLE found no nearby devices on a5. Radio coexistence and the NimBLE
central/observer roles *are* correctly enabled in the core-3 build, so pinning
this down needs on-device evidence. This build **logs BLE over USB serial**
(115200 baud):

- `[BLE] init: up|FAILED, internal heap X -> Y` at startup, and
- `[BLE] BMS scan: N seen` / `[BLE] web scan: N seen` on every scan.

If BLE still finds nothing, **capture the serial log during a scan and send it**:
`seen 0` with a healthy heap points at the radio/coexistence path; `FAILED` or a
tiny heap points at the controller not getting RAM. Two things to know: the
"scan for devices" button is disabled in **setup-AP mode by design** — configure
Wi-Fi first, then scan for your BMS from the dashboard in STA mode (which the Wi-Fi
fix above now keeps stable long enough to do).

## Please test
- Enter Wi-Fi through the setup AP → it connects and **stays** on your network.
- From the dashboard (STA), scan for your BMS. If it's empty, grab the USB serial
  log so the `[BLE]` lines can tell us exactly where it's failing.
