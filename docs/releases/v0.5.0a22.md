# R48Display v0.5.0a22 — alpha (arduino-esp32 3.1)

**Pre-release for hardware testing.** Install over **USB**.

This build turns **on-device firmware updates** back on — the payoff of the whole
3.x migration. It needs your hardware to confirm the last piece.

## On-device "Check for updates" (user-initiated)
Settings → Firmware Update → **Check for updates**. There are **no automatic
background checks** — it only looks when you ask.

- The check **tears BLE down first** to free the ~40 KB of internal RAM the TLS
  handshake needs, then restores BLE afterward. This is the memory fix that makes
  on-device checks viable on core 3 (a custom mbedTLS build was tried and
  abandoned — it couldn't build locally or on CI).
- The result tells you **how** an update installs:
  - **"installs on device"** — a same-generation update; hit **Install** and it
    updates over the air.
  - **"major update — install over USB"** — the target crosses the bootloader
    boundary (e.g. 0.4.x ↔ 0.5.x), which can't be done over the air; it links you
    to the USB installer instead.
- **Hours are saved before an on-device update reboots**, so an OTA never loses
  accrued hours — hours history is maintenance-critical.

## Please run the deciding test
After flashing a22, attach the USB serial console (115200), then Settings →
Firmware Update → **Check for updates**. Look for:

> `[fwupd] check: internal free X / largest Y (BLE down)`

- If the check **succeeds** and `largest` is ≳ 16 KB, on-device updates work on
  this device — the migration's goal is met.
- If it **fails**, send me that line; it shows exactly how much internal RAM the
  handshake was short by, and we choose the next step from there.

Carries a21's backup/restore + hours/pay reconciliation, and everything prior.
