# R48Display v0.4.7

**OTA from v0.3.0 or later is safe** — the partition table is unchanged.

## Update check no longer destabilizes the web UI
- The manual **Check for updates** used to tear Bluetooth down to free memory for the secure connection. On this hardware that both (a) didn't help and (b) could leave the web server unresponsive shortly after. The check is now a single, harmless best-effort attempt with no radio teardown.

## Why on-device update checks fail here (and what to use instead)
- Diagnostics confirmed the on-device GitHub check is **memory-bound** on this build. The TLS buffers in arduino-esp32 2.0.17 need two large contiguous internal-RAM blocks that simply aren't available alongside Wi-Fi, Bluetooth, and the display — even with Bluetooth torn down, the largest free block (~30 KB) isn't enough, and the framework's buffers can't be shrunk from the app.
- **Use the USB web installer for updates:** https://picklepc.github.io/R48Display/ — its version dropdown lists every release and installs over USB using your computer's TLS, which has none of these limits. The device's own check is left in place as best-effort but should be treated as informational only.
