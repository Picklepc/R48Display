# R48Display v0.5.0a15 - alpha fresh-install recovery

**Pre-release for hardware testing** - install over **USB**.

This build fixes the release packaging path that made erased/fresh installs
boot-loop on some Waveshare ESP32-S3 boards even when the same firmware worked
through direct PlatformIO USB flashing.

## Fresh install / erase fix

- Release `firmware-merged.bin` images now use the same ESP32-S3 **DIO**
  bootloader flash-mode header that PlatformIO uses for direct USB upload.
- The previous merged installer images were forced to **QIO** during packaging.
  App upgrades could appear fine on some devices, but an erased board can reset
  before the application starts if the bootloader header is wrong for that unit.
- GitHub Actions now checks the merged image header and fails the release build
  if it is not DIO.
- The local `tools/package_firmware.ps1` packaging script uses the same DIO
  merge mode and performs the same header check.
- The web installer may still default to the latest stable release, currently
  `0.3.6`; the Pages deployment normalizes served merged images to DIO while
  assembling the installer site.

## Display init fallback

- Adds a selectable display-panel init mode in Settings:
  - `generic` - the legacy Arduino_GFX ST77916 init path.
  - `waveshare` - the vendor ST77916 init table from the Waveshare demo.
- The default is `generic` so devices that worked before keep the legacy path.
- Changing the setting requires a reboot.
- `/api/status` and `/api/settings` expose the selected display init mode for
  troubleshooting.

## Install notes

- Use the web USB installer or flash `firmware-merged.bin` at offset `0x0` for
  erased boards, recovery, or the first 0.5.x install.
- Erasing flash is a factory reset. Wi-Fi, BMS selection, machine notes, hour
  counters, and maintenance history must be re-entered after erase.
- The 256 KB NVS partition layout is unchanged from v0.3.x. OTA still cannot
  rewrite the partition table, but this release fixes the merged USB image used
  for fresh installs.
- After a working 0.5.x USB install, later app-only OTA updates can be used
  again for normal upgrades.
