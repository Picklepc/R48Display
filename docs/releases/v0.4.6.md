# R48Display v0.4.6

**OTA from v0.3.0 or later is safe** - the partition table is unchanged.

## Maintenance page stability
- Fixed the Maintenance page crash/hang seen after v0.4.5 by removing large heap allocations from page load.
- `/app.js` now streams directly from flash instead of allocating the full shared JavaScript bundle as one large `String`.
- Settings and Maintenance page bodies now stream directly from flash instead of allocating their full HTML bodies before sending.
- Maintenance hour bars now use a compact `/api/hours` endpoint instead of pulling the full `/api/status` payload.
- The heatmap API no longer prebuilds a heap-heavy date-to-maintenance map. It streams compact maintenance completion pairs and the browser groups them.

## Reduced live web overhead
- The dashboard's live poll of the full `/api/status` payload slowed from every 2.5 s to every 5 s, roughly halving the recurring serialization work on the ESP32 while a browser tab is open.

## Firmware update check
- Consolidated to a single source — the installer's `versions.json` on GitHub Pages (the same list the web installer uses) — instead of trying that and the GitHub API in turn.
- On a failed secure connection, the error now reports the largest contiguous internal memory block alongside free heap, so a fragmentation failure (ample free heap but no large contiguous block for the TLS buffer) is distinguishable from plain exhaustion.

## Validation
- Built both PlatformIO environments successfully.
- Size remains steady at about 55.7% RAM and 38.0% flash.
