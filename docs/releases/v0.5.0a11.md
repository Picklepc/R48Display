# v0.5.0a11

Alpha pre-release for arduino-esp32 3.x BLE regression testing.

## Changes

- Keeps the 0.5.x framework migration, but pins pioarduino to `53.03.13-1`
  instead of `55.03.39`.
- This moves the build from Arduino-ESP32 3.3.9 / ESP-IDF 5.5.4 back to the
  older Arduino-ESP32 3.1.3 / ESP-IDF 5.3.2 line while staying on 3.x.
- Keeps GFX Library for Arduino at `1.6.6`. The earlier Arduino-ESP32 3.0.7 /
  ESP-IDF 5.1.4 line was tested but lacks LCD APIs required by this GFX version.
- Pins PlatformIO's registry `tool-esptoolpy` package to avoid the pioarduino
  esptool ZIP postinstall failure seen in GitHub Actions.
- Carries forward the v0.5.0a10 BLE protections: delayed BLE startup, passive
  scans, manual scan takeover, and scan-timeout cooldown.

## Why

v0.5.0a10 keeps Wi-Fi alive longer, but BLE scan still returns no devices and
can eventually trigger a reset. v0.3.6 used Arduino-ESP32 2.0.17 and BLE worked,
so this build tests whether the regression is specific to the newer pioarduino
3.3.9 / IDF 5.5 package rather than all Arduino-ESP32 3.x builds.

## Testing Notes

- Install from the GitHub web installer.
- After the web UI comes up, open Settings and run one BLE scan.
- If it still resets, the next recovery path is to return firmware development
  to the 0.4.x/Arduino-ESP32 2.0.17 core and replace direct ESP-to-GitHub TLS
  updates with a browser-assisted or reboot-to-minimal-update-mode updater.
