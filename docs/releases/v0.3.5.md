# R48Display v0.3.5

**OTA from v0.3.0 or later is safe** — the partition table is unchanged.

## Pay Records
- New **Pay Records** section on the Maintenance page: track payees, hourly rates, and working hours accumulated since the last payout — built for parent/teen chore-pay arrangements.
- **Mark Paid** closes the period, stores a payment history entry (last 20 per payee, with date range, hours, and amount), and starts the next period; the calculated amount can be overridden for bonuses or adjustments.
- Payment history drawer, per-payee notes, and CSV export.
- **Pay Pending** metric on the web dashboard.
- Enabled via the new **Enable Pay Records** checkbox in Settings — fully independent of daily activity tracking.

## Stability
- Fixed a crash when loading the Maintenance page: the activity heatmap API was sending thousands of tiny TCP chunks per year of history, fragmenting the ESP32 heap; day data is now sent in 64-day batches.
- Daily-activity rollover check throttled to once per minute (previously ran the time lookup thousands of times per second, contributing to freezes).

## Security Hardening
- User-supplied text (maintenance names/notes, payee names, Wi-Fi SSIDs, BLE device names, weather strings) is now HTML-escaped everywhere it is rendered in the web UI (stored XSS fixes).
- Cross-origin request guard on all state-changing API endpoints: browser requests with a mismatched `Origin` header are rejected with 403. Non-browser clients (curl, scripts, Home Assistant) are unaffected.
- Server-side length caps added to all settings, maintenance, and pay text fields.
- CSV exports now escape carriage returns.

## Fixes
- Day-based maintenance items now show **Not started** until their first completion instead of a misleading full countdown (e.g. "365d left" on a never-completed annual inspection).
- Fixed garbled `â` characters (broken em-dash encoding) in the pay cards, payment history, Mark Paid dialog, and alerts.
