# R48Display v0.4.10

**OTA from v0.3.0 or later is safe** — the partition table is unchanged.

## Web stability: reclaim memory from the update checker that couldn't work
The strongest remaining cause of the web UI going unresponsive was the on-device firmware update check. On this build it **can't succeed** — its secure connection needs ~16 KB of contiguous internal RAM the device can't provide (free heap was only ~19 KB) — and each failed attempt fragmented the heap enough to knock the synchronous web server offline. That's why the web went unresponsive right after every "Check for updates."

- **The update-check background task is no longer started**, reclaiming its **16 KB stack** — roughly doubling free internal memory — and removing the churn that destabilized the web server. The weather task's stack was trimmed too.
- **Settings → Firmware Update** now points to the USB installer instead of offering a check that can't run.
- Together with 0.4.9's JSON streaming, the web UI should now hold steady under sustained use.

On-device update checks **return in 0.5.0** (arduino-esp32 3.x), where the TLS buffers can be sized to fit this device. Until then, update over USB at **https://picklepc.github.io/R48Display/** or via Manual upload.
