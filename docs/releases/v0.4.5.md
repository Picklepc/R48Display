# R48Display v0.4.5

**OTA from v0.3.0 or later is safe** - the partition table is unchanged.

## Web app stability
- Settings and Maintenance no longer run the full `/api/status` live poll when those pages do not render live status fields.
- Settings now loads profile/theme/category metadata sequentially instead of opening a burst of simultaneous requests.
- The dashboard maintenance summary is throttled instead of re-fetching the full maintenance list every 2.5 seconds.
- The activity heatmap response now includes a compact maintenance-completion index, so the Maintenance page no longer calls one history endpoint per maintenance item on load.
- The firmware update checker now reads the lightweight GitHub Pages installer index before falling back to the heavier GitHub Releases API.

## Activity grid timekeeping
- The daily activity snapshot now retries immediately until the clock is valid, then throttles normally after a valid read.
- Day rollover now happens before the next hour delta is added, keeping new-day time out of the prior day.
- Charging time now rolls into standby hours, matching the mower install expectation that charging is non-driving/non-working time when the ESP32 remains powered.
- Current-day and rollover heatmap cells use the precise working-session log as a backstop for working hours. If the daily snapshot was seeded late, pay can still be correct and the annual grid now shows the mowing/working time instead of dropping it.
- Heatmap day buckets now round to the nearest tenth of an hour instead of truncating, so short sessions line up with Pay and dashboard rounding.
- Pay Records and Daily Activity can be enabled independently; the shared work-session log is active when either feature needs it.
- Custom Active/Working labels now flow through LVGL hour strings, web dashboard hour headings, Maintenance hour bars, annual heatmap tooltips, and Pay Records labels.
- The LVGL dashboard status pill is wider so charging labels such as "Charging" or "Recharging" do not wrap inside the rounded badge.

## Validation
- Built both PlatformIO environments successfully.
- Size remains steady at about 55.7% RAM and 37.9% flash.
