# v0.5.0a12

Alpha pre-release for arduino-esp32 3.x BLE/Wi-Fi coexistence testing.

## Changes

- Moves regular BMS BLE polling/scanning out of the main `loop()` and into a
  dedicated pinned BLE worker task.
- Makes the Settings-page BLE scan asynchronous: the web request starts a scan
  job and polls cached results instead of blocking the web server until NimBLE
  finishes.
- Routes manual reconnect, manual read, provisioning pause, and firmware-update
  BLE pause/resume through the BLE worker so one task owns NimBLE calls.
- Reduces manual scan stored-result pressure from 64 to 32 NimBLE results and
  returns at most 24 copied devices to the web UI.
- Adds BLE worker diagnostics to `/api/status` under `bms`: task running/busy,
  loop count, max loop time, stack high-water mark, and manual scan state.
- Adds conservative NimBLE build flags for the 3.x test path: one connection,
  central/observer use only, larger NimBLE task stacks, pinned NimBLE core, and
  a larger Arduino loop stack.

## Why

Reviewed mature 3.x BLE/Wi-Fi projects isolate BLE scan work in its own task and
avoid running scans directly inside the web-server path. This build applies that
pattern so BLE can stall or time out without wedging the settings page or main
dashboard loop.

## Testing Notes

- Install from the GitHub web installer.
- Confirm STA stays connected and the web UI remains responsive while BLE status
  cycles through waiting/scanning/searching.
- Open Settings and run `Scan for BMS`; the page should remain responsive while
  the scan is running and then show devices, no devices, or a bounded error.
- If it resets, capture `/api/status` after reboot and note the `bms.worker_*`
  and `bms.manual_scan` fields before the next patch.
