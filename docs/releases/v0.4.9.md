# R48Display v0.4.9

**OTA from v0.3.0 or later is safe** — the partition table is unchanged.

## Web-server stability
Targets the recurring web crash / unresponsiveness under sustained polling. The root cause was **heap fragmentation**: every `/api/status` (~6 KB) and `/api/live` response was serialized into one large `String` on a heap already shared with Bluetooth, the display, and Wi-Fi. Under repeated polling, a large contiguous allocation would eventually fail and the synchronous web server could no longer respond.

- **JSON responses now stream** to the browser in ~512-byte pieces instead of building the whole body as one `String` — roughly halving the per-request heap peak, which was the trigger.
- **The dashboard's live poll pauses when the browser tab is hidden** (and refreshes the moment you return), so a backgrounded dashboard no longer keeps the ESP32 serializing status JSON every 5 seconds.

If the web UI stays stable on this build across a long session with a tab left open, this is the fix; if it still degrades, the remaining pressure is the status `JsonDocument` itself, which is the next thing to stream field-by-field.
