# R48Display v0.5.0a7 — alpha (arduino-esp32 3.x)

**Pre-release for hardware testing** — install over **USB**.

This build fixes the **root cause** of the "connects for a minute, then falls back
to the setup AP" problem that persisted through a5/a6.

## Wi-Fi: the real cause was max modem-sleep on core 3
About 60 seconds after the last web interaction, the firmware promoted Wi-Fi to
**maximum modem-sleep** (`WIFI_PS_MAX_MODEM`) to save power. That was fine on the
old 2.x core, but on arduino-esp32 3.x — with Bluetooth coexistence running —
maximum modem-sleep starves the STA of beacons and **drops the connection**. The
device then fell back to the setup AP, "as if it never realized it connected." The
~1-minute timing was the idle power-save timer, not the link itself — which is why
the earlier fallback-logic fix (a6) couldn't help.

- **On core 3, Wi-Fi now holds at `MIN_MODEM` power-save** — the exact mode the
  stable first minute already ran at — so the STA link stays up. (The 2.x core
  keeps its original adaptive behavior.)
- The device now **latches "connected" on the actual got-IP event** and will not
  auto-revert to the setup AP once it has an IP. Automatic AP fallback only
  happens while validating brand-new credentials that never connect.
- Added `setAutoReconnect(true)` and **USB-serial Wi-Fi logging** — `[WiFi] STA
  got IP …` and `[WiFi] STA disconnected (reason N)` — so any remaining drop is
  diagnosable at a glance.

## This should also restore Bluetooth
BLE is paused while the setup AP is active, so the constant reverting kept it off
most of the time. With the STA link now stable, BLE runs continuously — scan for
your BMS from the dashboard. (The a6 `[BLE]` serial diagnostics are still in.)

## Please test
- Join Wi-Fi via the setup AP, then **leave it sitting for several minutes** — it
  should stay on your network and not fall back to the AP.
- Then scan for your BMS from the dashboard.
- If anything still drops, capture the USB serial log (115200) — the `[WiFi]` and
  `[BLE]` lines will show exactly what happened (e.g. a disconnect reason code).
